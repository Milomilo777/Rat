Okay, here is my plan:

R1: a removed rule shrinks the pf blocklist
- PASS: Removing a rule from `RulesModel` updates `ruleSet`. `Ledger.loop` runs `rules.refreshNetwork()` and `refreshBlocklist()` every 1.5s, which evaluates all `denied` entries against `rules.engine`. Addresses that now evaluate to `.allow` or `.ask` are excluded, and `enforcer.sync(wantedBlocklist)` is called, shrinking the pf blocklist.

R2: an app with a rule never prompts.
- PASS: `Ledger` checks `let verdict = matched?.verdict ?? rules.engine.defaultVerdict`. If it has a rule (e.g. `.allow` or `.deny`), it is not `.ask`. Alert is reported only if `verdict == .ask`. Additionally, `AlertCenter.revalidate()` skips queued alerts where `rules.engine.evaluate(c) != .ask`.

R3: alerts time out to the configured default.
- PASS: `AlertCenter.startTimeout()` uses `AppSettings.shared.alertTimeout` and auto-answers `allow` or `deny` based on `AppSettings.shared.alertTimeoutAllows`.

R4: imported rules arrive disabled and unapproved.
- PASS: `RulesModel.importRules` calls `engine.importRules(export, markUnapproved: true)`. `RuleEngine.importRules` sets `r.approved = false; r.enabled = false` for imported rules.

R5: state is written atomically and survives a crash mid-write.
- PASS: `Persistence.swift` and `RuleEngine.swift` use `.atomic` writes (`Data.write(to:options: [.atomic])`), and `Enforcer.swift` uses `atomically: true`.

R6: a malformed state file does not wipe user rules.
- FAIL: The application's rules are stored in `rules.json`. In `RulesModel.init`, if `store.loadSet()` fails (e.g., due to malformed JSON), it defaults to `RuleSet.standard()` via `var set = (try? store.loadSet()) ?? RuleSet.standard()`. Then `ruleSet = set` triggers a `scheduleSave()`, which immediately overwrites the malformed `rules.json` with an empty default ruleset, irreversibly wiping the user's rules.

R7: the update checker never runs code it downloads.
- PASS: `UpdateChecker.swift` checks the GitHub release API. When a new version is found, it calls `NSWorkspace.shared.open(u)` to open the release URL in the browser instead of downloading or executing code.

R8: timers and observers do not leak on window close.
- PASS: There are no `Timer` objects. The background sampling `Task { await loop() }` belongs to `Ledger`, which is an `@StateObject` tied to the app lifecycle, not a specific window. `NotificationCenter` observer in `RatApp.swift` is bound to the SwiftUI `.onReceive` view modifier, which removes itself automatically when the window is closed.

R9: no data race on shared state between the sampler and the UI.
- PASS: `Ledger` is `@MainActor`. It spawns background sampling using `Task.detached(priority: .utility)` which returns value types (`[ObservedConnection]`, `[TrafficCounter]`). These results are then safely ingested back on the `@MainActor` in `ingest(conns, traffic)`. Shared configurations (`RuleEngine`, `LocalRanges`) use `NSLock`.
